## 一、项目是什么

把鸿蒙 7 手机 / 平板实时镜像到 Windows，并在 PC 侧反向操作设备、双向传剪贴板。
目标基线 **1080p / 60fps / 端到端 <100ms**，无音频，Wi-Fi 优先，最多 3 台设备。

**当前阶段：功能侧已完成，剩人工验收。** 端到端已真机跑通（双路并行、切换零黑框、剪贴板双向、三键 + 拖动 + 滚轮）。

| 设备 | 型号 | 无线调试 | 分辨率 / 采集 |
|---|---|---|---|
| 平板 | MLR-AL00（MatePad），OH 7.0.0.111 / API 26 | `192.168.1.100:38803` | 1600×2560 |
| 手机 | HOP-AL10（Pura X Max 典藏，折叠展开），同版本 | `192.168.1.102:40663` | 1828×2584；ref 实际 914×1292（scale 2） |

- **手机 IP 就是 `192.168.1.102:40663`**（用户 2026-11-16 18:18 最终裁定；「103 是手机」已作废，勿再纠正）。
- **端口每次开机都变**，以设备屏幕显示为准；先 `tconn` 再判断是否在线。
- 两台均 `enabled=true` + `capture=ref`，启动走双路并行。**手机 capture 勿写 `hap`**（手机没装自有 HAP，必然失败）；手机 `enabled` 勿改 `false`（会显示「当前未接入」，但设备其实在线）。
- 设备名/型号只是 UI 标签。选设备按启用项的 `hdcTarget` 解析，启动时用 `param get const.product.model` 实测校正显示。判真机看 `logs/startup.log` 的 `[OK] <ip:port> 来源=live 设备型号=…`。
- `AddDevice` 建真条目后须 `RemovePendingDeviceUi(name)` 撤掉灰淡占位，否则标题栏 4 枚图标（用户要 2 枚）。

## 三、架构与关键实现

- **设备端**：ArkTS + C++ NAPI（`cpp/harmoscap.cpp`，1,297 行）+ AVScreenCapture + OH_VideoEncoder 零拷贝。
  采集 so 是 `screen_casting.so`（242 KB），触控用 `agent.so`（586 KB）——**推错绑不上 `@scrcpy_grpc_socket`**。
- **PC 端**：C# / .NET 8 + WPF + Media Foundation 硬解 + D3DImage 上屏；单文件发布 `HarmOsWin.exe`（自包含，双击即跑）。
- **hdc 桥**：所有 hdc 调用必须经独立控制台进程 `HarmOsWin.HdcBridge`（stdin/stdout 行式 JSON），`HdcRunner` 只是薄客户端。
  WPF 内直接跑 hdc 的九种常规排法全部失败（控制台 8/8 全过、WPF 必卡且位置随机），**勿再试**。
  桥响应读必须带超时，否则阻塞会锁死 `HdcSerial` 全局锁；会话失效桥内自动 tconn 重试一次（`[auto-reconnect]`）。
- **传输**：LAN + HWP v1.1 UDP 双通道 + 30ms 心跳；GATE-L0 通过，故**不上 P2P**（GATE-L1 未执行）。gRPC h2c 走 fport。
- **fport 规则存在 hdcd server 内存**：server 一死即成「僵尸监听」（端口 LISTENING 但 connect refused）。
- **注入**：唯一有效通道是 **uitest RPC**（PC 侧经 hdc fport，持久 socket）。
  **`AccessibilityExtensionAbility` 通道永久作废** —— 鸿蒙 7 系统不存在无障碍扩展服务，见第八节。
- **剪贴板**：设备→PC 走 `HCLIP` UDP 18766 + `PasteButton` 一次性读权限，PC 侧 `ClipInbox`；
  PC→设备**真写系统剪贴板**：`aa start -a ClipSetAbility -b com.harmos.mirror --ps cliptext '<base64>'`（敲字仅回退）。
- **窗口贴合**：`SwitchTo(id, refitWindow)` 默认 `false`，**仅两个用户点击入口传 `true`**；贴合在 `Loaded` 里延迟执行
  `FitWindowToDevice() → UpdateLayout() → ApplyStretchForAspect()`。**勿把贴合挪回同步路径**（11-13 曾致进程消失），
  **勿删 `UpdateLayout()`**（否则 stage 比例读旧值）。18:57 真机验收零黑框（平板 551×911 / 手机 623×911 Fill）；
  日志「窗口 0.625/0.707」是 stage 客户区比例，整窗含 chrome 为 0.605/0.684，**勿误判失败**。
- **P0 首帧提示**：等首帧 >10s（`pres==0 && Streaming`）在状态栏/占位页提示「设备可能已息屏 —— 请点亮屏幕或轻滑一下」，首帧到达后自动复位。只改 UI 呈现，未动看门狗判死策略、未 hdc 唤屏、未动视觉息屏降级。
- 色彩公式 **BT.601 limited 不改**（红字偏粉紫是 App 自身配色，已证伪为管线缺陷）。

## 九、开发与维护硬规则

1. **调试一律走无线**，统一 `scripts\hdcw.sh`，**禁止 USB 调试**（hdcd 会踢掉 TCP 通道）。hdc 严格串行、每次前必 `tconn`；Git Bash 需 `MSYS2_ARG_CONV_EXCL='*'`；中文绝对路径用相对名；不用 `hdc tmode port`；脚本带 UTF-8 BOM。
2. **编译 / 装机 / 启动 / 发布须用户当次逐次授权**（一次授权只管当次）。改完代码 ≠ 可以编译。
3. **工具会话里启动 WPF 会被作业对象连带杀掉**，须 `Start-Process explorer.exe -ArgumentList '"<exe>"'` 由桌面外壳拉起。
4. **启动连不上的四层防线勿删**：`MainWindow.cs:905` 整体自愈重试 → `HdcTargetResolver` 空列表按 IP 分缓存 tconn + 候选重试 + 端口扫描 → 桥 `RunHdc` 会话失效自动 tconn 重试一次 → 双启用配置 + 配置副本 md5 一致 + exe 与桥同目录。三条禁止回退：手机 `enabled` 勿改 false、`capture` 勿改 hap、IP 勿改回 103。
5. **禁止拿用户私人应用当试验场**（备忘录、微信等），自测只用自有 HAP（`InputProbePage.ets` / `ClipSetAbility`）。
6. 设备端**禁用管道 `|`**（grep 等空 stdin 出 0 字节），用 `grep xxx /proc/net/unix`、`ps -ef`；`hdc file send` 用相对名 + 透传 WorkingDirectory + 先 `rm -f`；判进程存活用 `Process.HasExited` 轮询。
7. **清 `tmp/` 前必做文档引用检查**。**别碰**：`logs/`、`.hdcw/`、配置副本、`tmp/refout/`、`clip-anchor.json`、被引用的证据文件。
8. Windows 送回收站**禁用 `Add-Type`**（安全策略拦运行时编译 .NET），用 Python ctypes `SHFileOperationW` + `FOF_ALLOWUNDO`，每批 ≤10 逐批校验，先做逐文件 md5 副本。
9. 参考项目（ohscrcpy / hnscrcpy / lanlink / oink）**只借鉴思路，代码一行不能抄**，红线见 `docs/参考项目-能力清单.md`。
